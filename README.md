## Описание проекта

Приложение позволяет зарегистрировать пользователя, войти с логином и паролем, получить JWT, создать запись и прочитать **только свои** записи. Чужие записи по токену другого пользователя не возвращаются.

Для HTTP-запросов используется Spring Web MVC, для доступа - Spring Security и OAuth2 Resource Server, для хранения — Spring Data JPA и H2. 

Код разделён по назначению: `auth` обрабатывает регистрацию и вход, `user` хранит пользователей, `post` работает с записями, `config` настраивает безопасность, `common` формирует ответы об ошибках. Контроллеры принимают HTTP-запросы, сервисы выполняют правила приложения, репозитории обращаются к базе данных.

## Список эндпоинтов

### POST /auth/register — регистрация

Метод доступен без токена. Логин `username` должен содержать 3–32 символа: латинские буквы, цифры, точки, дефисы или подчёркивания. Пароль `password` должен содержать 12–72 символа и не более 72 байт в UTF-8.

Формат запроса:

```json
{
  "username": "student1",
  "password": "long-unique-password-1"
}
```

Успешный ответ — **201 Created без тела**. Регистрация не выдаёт JWT; для получения токена нужно выполнить вход. Повторная регистрация даёт `409 Conflict`, неверный формат полей — `400 Bad Request`.

### POST /auth/login — вход

Метод доступен без токена. При успешной проверке пароля возвращает подписанный JWT на 15 минут.

Формат запроса:

```json
{
  "username": "student1",
  "password": "long-unique-password-1"
}
```

Формат ответа:

```json
{
  "accessToken": "<JWT>",
  "tokenType": "Bearer",
  "expiresInSeconds": 900
}
```

Неверная пара логин/пароль даёт `401 Unauthorized` с одинаковым сообщением независимо от того, существует ли логин.

### GET /api/data — получение своих записей

Требуется заголовок `Authorization: Bearer <JWT>`. Ответ - JSON-массив из не более 100 последних записей текущего пользователя. У нового пользователя после входа массив пуст: `[]`.

Пример формата ответа после создания записи:

```json
[
  {
    "id": 1,
    "title": "Моя запись",
    "content": "Текст для лабораторной",
    "createdAt": "2026-09-30T10:00:00Z"
  }
]
```

Дата и идентификатор в примере иллюстративные. Без токена, с неверным или просроченным токеном метод возвращает `401 Unauthorized`.

### POST /api/data — создание своей записи

Требуется заголовок `Authorization: Bearer <JWT>`. Поля `title` и `content` обязательны; их максимальная длина — 200 и 2000 символов соответственно. Владелец не указывается в запросе: сервер берёт его из проверенного JWT.

Формат запроса:

```json
{
  "title": "Моя запись",
  "content": "Текст для лабораторной"
}
```

Успешный ответ — `201 Created` и JSON созданной записи с полями `id`, `title`, `content`, `createdAt`, как в примере выше.

## Защита от SQL-инъекций

Доступ к H2 реализован через **Spring Data JPA**. Например, `UserRepository.findByUsername(username)` ищет пользователя, а `PostRepository.findTop100ByOwnerOrderByIdDesc(owner)` выбирает записи по владельцу. Значения передаются в запрос как параметры; код приложения не собирает SQL конкатенацией строк с пользовательским вводом. Поэтому введённый текст не может изменить структуру SQL-команды.

Валидация логина и полей записи дополняет параметризацию, но сама по себе не заменяет её. Интеграционный тест также проверяет отказ во входе при SQL-подобной строке вместо логина.

## Защита от XSS-атак

API возвращает JSON и не формирует HTML-страницы. Перед созданием ответа `PostResponse` сервис `DataService` применяет `HtmlUtils.htmlEscape` к пользовательским полям `title` и `content`. Например, введённое `<script>` возвращается как `&lt;script&gt;`. Экранирование проверяется интеграционным тестом при создании и чтении записи.

Если к API позже добавить веб-интерфейс, его разработчику также понадобится безопасный вывод данных в соответствующем контексте HTML или JavaScript. JSON-сериализация сама по себе не заменяет такую защиту.

## Реализация аутентификации пользователя

При регистрации пароль хэшируется **BCrypt** с фактором стоимости 12; в H2 хранится только хэш. При входе пароль сравнивается через `PasswordEncoder`, а API не возвращает пароль или хэш. Для неизвестного пользователя сервис выполняет сравнение с фиктивным BCrypt-хэшем и отвечает общей ошибкой.

После успешного входа `JwtService` создаёт JWT с подписью **HS256** и сроком действия **15 минут**. Токен содержит `subject` пользователя, `issuer` приложения и время истечения. Ключ берётся из переменной окружения `JWT_SECRET_BASE64`; после Base64-декодирования он должен содержать не менее 32 байт. Значение ключа не хранится в репозитории.

Spring Security работает без HTTP-сессии. Открыты только `/auth/register` и `/auth/login`; остальные адреса требуют Bearer JWT. OAuth2 Resource Server проверяет подпись, срок действия и `issuer`. Контроллер получает подтверждённого пользователя из токена, а сервис создаёт и читает записи только этого пользователя. Клиент не передаёт владельца записи в запросе.
